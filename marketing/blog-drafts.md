## 草稿一：《为什么你看到的 token 价格是假的》（主推 · Linux.do / V2EX / 知乎）

### 开头（反直觉结论）

先说结论：你在任何一张"AI API 比价表"里看到的数字，大概率是错的——
不是造错了，而是**过期了**。

我们盯了一晚 OpenRouter 的公开价格，kimi-k3（moonshotai/kimi-k3）的
输入价一天内：

| 时间 | 输入价 / 1M |
|---|---|
| 10-25 晚 | ¥1.7208 |
| 10-26 晚 | ¥1.1592（-33%） |
| 几分钟后 | ¥1.0944（-6%） |
| 次日凌晨 | ¥1.1448（+5%） |

三次都是真实调价，不是抓取噪声——我们对最后一次变化做了连续 3 次间隔
采样确认。同一天，OpenRouter 还下架了 qwen3.8-max，上线了它的 0902 快照版。

你三天前收藏的比价表，现在可能整体作废。

### 第一层：价格会动

绝大多数比价内容是"写的时候对"。要让它持续对，只有一条路：
**自动采集 + 自动复核 + 自动失效**。

我们给 token比比 做的机制：

1. 每日自动抓取 OpenRouter、SiliconFlow、Anthropic、智谱的公开价格；
2. 与公开来源逐字段比对，完全一致才挂"已核验"徽章；
3. **源站改价或模型下架时，已核验徽章自动撤销**（这一步最重要——
   一个还在挂"已核验"的过期价格，比一个明说"待核验"的价格危害大得多）；
4. 每次变动留痕：检测时间、前后值，全公开（[链接]/data-status）。

### 第二层：标价便宜 ≠ 真的便宜

就算价格是新的，标价也不是你付的钱。真实成本：

> 有效成本 = 标价 × 充值系数 × 模型倍率 × 分组倍率

举个真实库里的例子：同样是"1 元买额度"，
`1 CNY = 1.2 credits` 和 `1 CNY = 0.8 credits` 意味着 1.5 倍的差价，
但两家页面上的"单价"可以写得一模一样。

订阅也一样：月费便宜的套餐，额度可能只覆盖特定模型、按周重置、
超额单价是标价的三倍。**订阅 vs 按量**的真正判据是"破局点"——
你的月用量越过它，订阅才开始划算。

### 第三层：样例数据在冒充真实数据

很多新产品上线时会填"示例价格"让页面不空着。问题不在于有样例，
而在于**样例和真实数据长得很像**。

我们的处理：比价页默认只显示已核验价格；样例要手动切换才出现，
且全程标注"样例数据，不构成采购参考"；分享出去的卡片会如实写
"已核验 · 来源复核"或"样例数据"，不会混。

### 结尾（工具 CTA）

token比比 把按量、订阅、积分、卡密四类购买路径放在同一口径里算真实成本：

- 比价（默认只看已核验）：[链接]/models
- 每次降价都会出现在这里：[链接]/price-drops
- 想第一时间知道降价：RSS [链接]/feed.xml
- 发现数据错误：直接在站内提交纠错，带来源链接的会被优先处理

数据全公开、方法全公开、错误欢迎指正。

## 草稿二：《我们如何自动核验 AI 价格（并抓到一天三次调价）》（开发者向 · V2EX / 掘金 / GitHub）

### 管线全景

```
每日 03:45（systemd timer）
  ├─ collect:openrouter / siliconflow / official   # 抓公开源
  ├─ import:prices                                  # 逐条合并（价格没变保留核验状态）
  ├─ review:demote-stale                            # 源站不认可 → 撤销已核验徽章
  ├─ changelog:prices                               # 与上一个快照比对 → 变动留痕
  ├─ history:prices                                 # 快照序列 → 价格历史
  ├─ snapshot + quality:report                      # 留档 + 质量报告
  └─ build + restart                                # 静态页重建
```

### 三个值得展开的设计

**1. "已核验"是一枚可以自己消失的徽章。**
核验的定义很严格：重新抓取公开源，输入价、输出价、缓存价逐字段一致才算。
但这只能证明"当时一致"。所以源站再次改价或模型下架时，徽章必须自动降级。
我们真抓到过"幽灵核验"：qwen3.8-max 在源站下架后，库里那条价格还挂着
"已核验"——这就是 demote-stale 存在的原因。

**2. 变动要留痕，且基线是"上一个快照"而不是"最初快照"。**
前者回答"这一轮发生了什么"，后者会随时间膨胀成流水账。
每条变动记录：检测时间、字段、前后值，RSS 直接输出（/feed.xml）。

**3. 数据出去必须带着状态。**
PNG 分享卡、iframe 嵌入卡、公开 API 的每条记录都带
`dataStatus + verificationMethod + lastVerifiedAt`。数据被引用到哪里，
"这是哪天的、怎么核验的"就跟到哪里。

### 开放数据（免费）

```
GET /api/prices                      # 默认仅已核验，60 次/分钟/IP
GET /api/prices?format=csv           # Sheets IMPORTDATA / Excel WEBSERVICE 直连
GET /api/prices?model=glm-5-3-flash  # 按模型过滤
```

响应 meta 带数据截至时间与已核验占比，消费方可以自证引用的新鲜度。
要求只有一个：署名。

文档：[链接]/data-api · 数据状态：[链接]/data-status

### 一句实话

这套管线的成本是一台 2 核 8G 的机器加一个 cron。它不酷，但它让
"我们比别的比价表可信"变成一个可验证的声明，而不是一句口号。
