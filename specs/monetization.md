# token比比 盈利方案（Monetization Spec）

> 2026-10-26 夜间打磨轮产出。原则：**盈利必须建立在数据可信之上**，所以本方案
> 前半部分是真实性/实时性的护城河建设，后半部分是三个已经写进产品的收入入口。

## 0. 立场：为什么"真实性/实时性"是盈利的前提

比价产品唯一不可替代的资产是**信任**。用户带着钱来做决策，谁的数据可信谁就有
收费资格。本轮对真实性/实时性做了三轮实测验证：

1. **全量来源复核**：`npm run review:sources` 重新抓取 OpenRouter / SiliconFlow /
   Anthropic / 智谱四个公开源，逐字段比对。结果 16 条可比对价格中 13 条完全一致，
   并暴露出 2 条真实问题：
   - `openrouter-kimi-k3-credit` 源站已改价（输出价 77.76 → 144）而库里还是旧价；
   - `openrouter-qwen3-8-max-credit` 模型已在源站下架，却仍挂着"已核验"徽章
     （幽灵核验——比"待核验"更大的真实性漏洞）。
2. **价格漂移实测**：kimi-k3 当日在 OpenRouter **连续降价两次**
   （输入价 1.7208 → 1.1592 → 1.0944，3 次采样间隔确认），证明"已核验"只是时点
   声明，实时性必须做成产品能力而不是运营口号。
3. **管线端到端验证**：采集 → 导入 → 变动记录 → 快照 → 质量报告全链路在本机
   跑通，数据追平到源站最新价（14 条已核验 / 1 条待核验 / 9 条样例）。

### 针对性加固（已上线）

| 漏洞 | 修复 |
|---|---|
| 幽灵核验：源站改价/下架后"已核验"永不失效 | `npm run review:demote-stale`：与实时源不一致的已核验记录自动降级为待核验 |
| 复核命令依赖未入库的映射文件，新环境直接崩溃 | `review-prices.mjs` 容忍映射缺失，开箱即用 |
| 用户看不到数据多新 | 首页/比价页新鲜度横幅 + `/data-status` 数据状态页（分平台核验统计 + 最近价格变动 + 核验方法说明） |
| 过期数据无声混在新鲜数据里 | 价格表更新时间列分层预警（3 天临近过期 / 7 天过期标红） |
| 价格变动无记录 | `npm run changelog:prices`：基线快照对比，生成 `data/price-changes.json` 并在数据状态页公示 |

## 1. 收入入口（全部已实现，全部可见）

### ① 广告位（/advertise）

- **形态**：固定 4 个位次（首页推荐位 ×1、比价页横幅 ×1、页脚文字链 ×2），全部
  明确标注"广告/赞助"，售完即止。
- **定价**（首发期，见 `data/ad-products.json`，运营改价不动代码）：
  - 首页推荐位 ¥980/月（刊例 ¥1,680）
  - 比价页横幅 ¥580/月（刊例 ¥980）
  - 页脚文字链 ¥280/月（刊例 ¥480）
- **自助流程**：页面选位 → 表单申请（落盘 `data/sponsor-leads.jsonl`）→ 1 个
  工作日内报价排期。MVP 阶段"先占位后付款"，未上架不收费。
- **红线**（页面明示，不可协商）：数量固定不加塞；赞助不影响价格、评分、排序；
  不接受无法核验的宣传表述。

### ② 数据 API 订阅（/data-api + /api/prices）

- **形态**：把价格数据本身变成商品。免费层已上线生产可用：
  `GET /api/prices`（默认仅已核验价格，60 次/分钟/IP，带 X-RateLimit-* 响应头，
  meta 附带数据截至时间与已核验占比——消费方可自证引用的是多新的数据）。
- **定价**：
  - 免费层 ¥0：60 次/分钟，CC BY 署名转载；
  - Pro ¥199/月：10,000 次/天，价格变动 Webhook 推送、30 天历史、商用免署名；
  - 企业层定制：专属配额与 SLA、全量历史导出、定制字段、发票合同。
- **开通**：Pro/企业层走页面表单线索（同一 leads 汇点），1 个工作日人工回复。
  MVP 不建支付与账号系统，先验证付费意愿再投入。
- **为什么敢收费**：只有与源站逐字段一致的记录才是 verified；源站改价/下架时
  徽章自动撤销；每次调价有检测时间与前后值。这套真实性机制本身就是差异化卖点。

### ③ 推广分成 / AFF（机制已贯通）

- **形态**：`providers.json.affiliateUrl` 字段已加入数据模型与类型；配置后平台
  详情页"访问官网"自动切换为带追踪的推广链接（`rel="sponsored nofollow"`），
  页面同步出现"含推广链接"披露。
- **现状**：8 个平台 `affiliateUrl` 均为 `null`（无商业关系）。谈下第一个分成
  账号（优先：OpenRouter、SiliconFlow、AIHubMix）填一个字段即生效。
- **透明底线**：AFF 有披露；无披露的链接一律不带返佣。

## 2. 单位经济（保守估算，按当前成本结构）

- **成本**：ECS 2核8G 一台（已有）+ 域名；采集与复核全自动，人工只在授权与
  纠错复核上，估 5 小时/周。
- **路径 A（广告位）**：4 个位次若在上线 60 天内以首发价售出 3 个，
  ≈ ¥(980+580+280×2)/月 ≈ **¥2,120/月**。
- **路径 B（数据 API）**：面向社区工具/机器人/内容作者，20 个 Pro
  ≈ **¥3,980/月**；这是天花板最高的一条：数据边际成本≈0。
- **路径 C（AFF）**：按中转站行业返佣水平（首充 10%-30%），流量起量后弹性最大，
  但不确定性也最大，作为被动叠加项不进 90 天承诺。
- **90 天目标**：月固定收入（A+B）≥ ¥5,000，覆盖成本后验证 PMF，再决定投入
  更多平台/模型覆盖。

## 3. 增长飞轮（为什么这三条能互相加速）

真实性机制（复核/降级/变动留痕）→ 用户信任 → 社区自发引用比价结论（分享卡
+ embed 组件已具备）→ 反向给 /data-api 免费层导流 → 第三方内容二次传播
→ 广告位位次价值上涨。**数据越真，流量越值钱，三条收入线同向放大。**

## 4. 90 天执行清单

| 阶段 | 动作 | 验收 |
|---|---|---|
| 第 1-2 周 | 部署本轮改动到 ECS；接第一个 AFF 账号 | /data-status 公开可访问；affiliat 链接带追踪参数 |
| 第 3-4 周 | 冷启动分发（marketing/ 工具包已备）；在社区放免费 API 案例 | /api/prices 有第三方真实调用 |
| 第 5-8 周 | 谈 2-3 家广告主试用；上线 Pro 层手动开通 | 首个广告位成交 / 首个 Pro 订阅 |
| 第 9-12 周 | 根据 leads 转化数据调价；扩展 302.AI/AIHubMix 采集 | 月收入 ≥ ¥5,000 |

## 5. 风险与对策

- **源站反爬/封锁**：采集器走公开 API 与公开页面，频率克制（每日 1 次）；
  被封时降级为人工周核验并公示。
- **样例数据误导用户**：比价页默认只展示已核验；样例全程标注；`/data-status`
  公示核验方法。剩余 9 条样例价格为套餐/充值/卡密关联数据，待逐条核验后转正。
- **单一收入依赖**：三条线并行，广告位与 API 独立成单，AFF 只做增量。
