# token比比 — 竞品与计费维度调研（Draft）

- **日期**：2026-10-21
- **状态**：调研结论已形成，等待产品确认

## 1. 调研对象

### 1.1 Oken
- **定位**：AI 模型全网比价 + 可用性监控。
- **核心特点**：
  - 模型级输入价、输出价、缓存价
  - 模型一致性、token 消耗、稳定性
  - 平台线路、计费方式、支付方式、客服、发票、充值平台等字段
- **主要限制**：
  - 页面中的计费方式当前主要展示为「按量」
  - 对订阅、积分/点数、卡密/兑换码等购买路径的结构化比较不足
- **可借鉴点**：
  - 模型详情页 + 线路列表
  - 公开免责声明
  - “充值汇率”概念

### 1.2 PriceAI
- **定位**：AI 低价卡网订阅与中转 API 比价雷达。
- **核心模块**：
  1. 官方订阅
  2. 卡网订阅
  3. 官方 API
  4. 中转 API
  5. API 中转模型检测
- **可借鉴点**：
  - 先按“购买路径”分流，再做比价
  - 数据字段包含充值倍率、模型倍率、上游类型、账号池、支付方式、退款规则
  - 明确声明收录不等于推荐，商业合作不影响自然排序
- **商业模式参考**：
  - PriceAI 设置多个赞助位：
    - 全站顶部横幅
    - 首页生态合作位
    - 官方 API 合作位
    - 中转 API 频道赞助位
    - 底部赞助展示区
  - 所有赞助均明确标注为广告 / 赞助 / AFF，且不改变客观排序

### 1.3 New API
- **定位**：开源 AI 网关与自部署 API 中转站。
- **关键证据**：
  - 官方文档明确支持 **钱包与订阅**
  - 钱包功能包括：余额、在线充值、兑换码、订阅计划、我的订阅、邀请奖励
  - 订阅计划包含：价格、有效期、总额度、额度重置、购买上限、升级分组、降级分组
  - 模型广场支持标准价格 / 充值价格切换
- **结论**：
  New API 生态本身就证明了 **积分 / 点数 / 额度、兑换码、订阅套餐** 是真实存在且需要结构化比较的维度。

### 1.4 OpenRouter
- **定位**：多模型统一 API。
- **关键证据**：
  - Standard / Business 采用 **购买 credits + 按量扣费**
  - Free、Standard、Business、Enterprise 分层
  - 平台费用在 credits 购买时收取
  - 模型 token 价格仍按 provider list price 计算
- **结论**：
  “积分 / credits”不是小众玩法，而是成熟平台的常见购买方式。

## 2. 是否存在按积分或网卡购买的平台？

### 结论
**存在，而且需要纳入产品，但拆分方式要谨慎。**

| 维度 | 是否存在 | 建议处理方式 |
| --- | --- | --- |
| **按量计费** | 存在 | 一级核心维度 |
| **订阅计费** | 存在 | 一级核心维度 |
| **积分 / 点数 / credits / 额度** | 存在 | 一级核心维度，必须记录充值汇率、余额有效期、最低充值、折扣 |
| **卡密 / 兑换码 / 网卡** | 存在 | 作为购买路径和支付方式，不宜直接当价格维度 |

### 为什么
1. **积分 / credits / 额度**会直接改变真实成本：
   - 平台 A 标价低，但充值汇率差，实际更贵
   - 平台 B 标价高，但充值折扣大，实际更便宜
   - 若不记录，用户会被表面单价误导
2. **卡密 / 兑换码 / 网卡**本质上是获取额度或服务的路径：
   - 影响支付方式、购买门槛、售后、风险
   - 不一定改变 token 单价
   - 应记录在“购买路径 / 支付方式 / 风险”里，而不是硬塞进价格公式

## 3. 产品应新增的维度

### 3.1 必须新增
1. **订阅套餐**
   - 月费 / 年费
   - 包含额度
   - 额度重置周期
   - 模型范围
   - 分组升级 / 降级
   - 并发和限速
   - 超额规则
2. **积分 / 点数 / credits / 额度**
   - 充值汇率
   - 折扣
   - 最低充值
   - 余额有效期
   - 是否可退款
3. **卡密 / 兑换码**
   - 是否支持
   - 有效期
   - 使用规则
   - 售后边界
   - 是否公开可核验
4. **有效成本**
   - 标价 × 充值系数 × 模型倍率
   - 订阅额度折算后的每 1M tokens 成本
   - 起步门槛
5. **支付与风险**
   - 支持的支付方式
   - 发票
   - 退款政策
   - 客服
   - 合规与上游披露

### 3.2 暂不建议新增
1. **复杂能力评分**
   - 可以先用模型标签，不必 MVP 做完整 benchmark
2. **真实交易**
   - 会引入支付、风控和售后复杂度
3. **全自动化采集**
   - 初期人工核验优先，避免脏数据破坏信任

## 4. PriceAI 广告位商业模式评估

### 4.1 优点
1. **变现路径清晰**
   - 面向中转 API、网关、云服务、开发者工具、支付、监控等高相关广告主
2. **不直接伤害用户**
   - 只要标注清楚，用户可以理解这是广告
3. **可保持排序独立性**
   - PriceAI 明确声明赞助不影响排序
4. **适合垂直社区**
   - 开发者对基础设施服务有天然需求
5. **轻资产**
   - 不需要自建交易、支付和客服

### 4.2 风险
1. **需要流量**
   - 没有足够 PV 时，广告位很难卖出
2. **信任成本**
   - 广告如果过密，会削弱比价工具的公信力
3. **销售成本**
   - 需要处理素材、审核、投放、结算、发票
4. **竞争冲突**
   - 中转 API 广告主和被比价对象存在天然张力
5. **定价困难**
   - 缺少足够曝光数据时，很难定价

### 4.3 结论
**广告位是可行的变现补充，但不适合作为 0-1 阶段的核心收入模型。**

更好的路径是：

1. **先积累数据与流量**
2. **建立信任**
3. **再引入少量高相关赞助位**
4. **同步做 AFF / 合作收录 / 数据服务**

## 5. 竞争机会

1. Oken 强在模型级价格与稳定性。
2. PriceAI 强在购买路径分流与商业规则。
3. token比比的机会是：
   - **把两者合并，并补上“有效成本”**
   - 把订阅、积分、卡密、兑换码纳入同一套计算
   - 把营销和自然传播前置到产品设计中
