## 1. 设计原则

1. **结论优先**
   - 先给“真实成本”，再给详细字段。
2. **可解释**
   - 每个关键数字旁边要有来源或解释。
3. **移动端优先**
   - 核心操作在手机上完整可用。
4. **低装饰**
   - 少用复杂插画，更多用表格、卡片、徽章和状态色。
5. **信任感**
   - 用“来源 / 更新时间 / 核验状态”降低疑虑。
6. **营销友好**
   - 每个核心页面都要能生成分享卡片或链接。

## 3. 核心页面设计

## 3.1 首页

### 目标
用户 5 秒内理解产品价值，30 秒内开始计算。

### 页面结构
1. **主标题区**
   - 标题：`不要只看 token 单价`
   - 副标题：`先看真实到手成本`
   - 主按钮：`开始计算`
   - 次按钮：`查看模型比价`

2. **四类购买路径**
   - 按量计费
   - 订阅套餐
   - 积分 / 点数
   - 卡密 / 兑换码

3. **真实成本对比卡片**
   - 展示同一个模型在不同购买路径下的有效成本。

4. **成本计算器**
   - 输入模型与用量
   - 输出推荐路径

5. **数据可信度说明**
   - 来源、更新时间、核验方式

6. **分享区**
   - 生成卡片
   - 复制链接
   - 嵌入代码

### 关键交互
- 输入模型名，自动补全。
- 输入月输入 / 输出 tokens，实时更新结果。
- 切换购买路径，表格与图表联动。

## 5. 状态设计

## 5.1 空态
- 没有模型数据
- 筛选结果为空
- 平台未收录
- 订阅套餐未提供

## 5.2 加载态
- 骨架屏
- 不闪烁
- 保留页面标题

## 5.3 错误态
- 数据加载失败
- 计算参数无效
- 链接过期
- 无权限

## 5.4 禁用态
- 未选择模型
- 用量输入为空
- 数据未核验
- 商业关系冲突

## 7. 可访问性要求

1. 表格有 `caption` 和语义化表头。
2. 按钮可键盘访问。
3. 颜色对比度 ≥ 4.5:1。
4. 图表有文本替代。
5. 不只靠颜色表达风险，同时使用文字标签。
6. 表单错误与提示使用 `aria-live`。
7. 动画可关闭。

## 8. 文案规范

- 数字统一保留 2 位小数。
- 金额统一显示币种。
- 更新时间显示“YYYY-MM-DD HH:mm”。
- 未核验数据使用“待核验”；已核验数据标明“人工”或“来源复核”。
- 样例数据必须明确标注，默认不参与模型比价排名；用户切换“全部价格”时显示风险提示。
- 风险提示使用客观语言，不夸张。
- 商业内容使用“广告 / 赞助 / AFF”明确标注。

## 9. 交付给开发的要求

1. 所有页面提供 Markdown 设计说明。
2. 核心组件提供字段清单。
3. 状态设计必须实现。
4. 移动端优先。
5. 分享卡片需可导出 PNG。
6. 计算器结果需可保存为 URL 参数。
7. 表格支持键盘排序。
